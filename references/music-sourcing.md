# BGM 搜索、许可、试听与归档

本步骤在分镜定时之前执行。目标是找到适合活动、且有当前用途依据的音乐，不是给视频随便铺一条背景音。下面的来源是检索入口，不是永久许可白名单。

## 1. 先确定用途和音乐需求

继承已确认的发布范围：私人预览、活动宣传、商业项目、公开样例，以及是否需要再分发音频原文件。普通宣传不默认是非商业用途；用途不明且影响许可选择时询问。

根据活动氛围和内容确定音乐需求：目标时长、能量变化、速度范围、器乐/人声、是否有旁白、需要的重复节奏和结尾。不能只按曲名或“欢快”等标签选定。用户指定音乐时尊重选择，补齐来源；许可未核实时可做本地预览，不能标为已满足公开发布条件。

## 2. 搜索来源

可联网时先访问当前官方曲目页、许可页与下载说明；有合适的官方接口优先使用，接口条款与曲目许可分别核验。无网络或无浏览能力时说明限制，请用户提供来源链接/许可记录或下载文件，不编造检索结果。

| 来源入口 | 定位 | 必查事项 |
| --- | --- | --- |
| https://incompetech.com/music/royalty-free/ | 优先候选入口之一 | 具体曲目的CC版本、署名文字、免费下载方式；不要用付费方案代替已有免费许可而不告知 |
| https://pixabay.com/music/ | 一般成片配乐备选，不视为开放许可素材库 | 当前平台条款、独立分发限制、曲目Content ID信息、可获得的下载证明 |
| https://www.jamendo.com/ | 条件候选，可评估官方API | 曲目许可与API用途限制、凭证、下载允许字段；可播放不等于可下载 |
| 作者官网或其他开放许可曲库 | 扩展候选 | 原始作者/权利人、具体录音许可、下载入口和来源真实性 |

FreePD原站在编写本规则时显示关闭，不作为默认可用下载源。镜像或聚合站需追溯原始曲目和许可，不能因名称相近就继承原站信任。网站状态和条款会变化，每次使用重新确认。

不要绕过验证码、登录、付费墙、下载限制或接口限制。不批量抓取曲库；按本次需求获取少量候选。下载URL仅从已核验页面或接口取得，不猜路径。

## 3. 先筛许可，再花时间编排

公开演示优先选择明确CC0或CC BY的录音，逐曲核验，不把整个网站都标记为同一种许可。曲谱公版不代表某个录音也公版。

- **CC0**：保存对应作品的声明与来源，仍检查来源可靠性。
- **CC BY**：记录准确版本与署名要求；附作者、曲名、来源、许可链接和剪辑等修改说明。
- **NC**：不用于默认活动推广/商业候选；确为非商业且满足条件时单独记录。
- **ND**：默认排除视频配乐候选；音乐与运动画面同步在CC规则下属于改编。除非取得覆盖此用途的额外许可。
- **SA**：不作为简单默认候选；先确认成片的共享方式是否可满足适用要求，不能把Skill的MIT许可套在音乐或视频上。
- **自定义平台许可**：分别检查成片使用与音频原文件再分发，不能仅写“royalty-free”。

依据入口：
- https://creativecommons.org/legalmusicforvideos/
- https://creativecommons.org/faq/
- https://incompetech.com/music/royalty-free/licenses/
- https://pixabay.com/service/terms/
- https://pixabay.com/service/faq/
- https://devportal.jamendo.com/api_terms_of_use
- https://developer.jamendo.com/v3.0/tracks/file

许可有疑点时换候选或请用户提供授权依据；不保证“绝无版权问题”。Content ID标记是需要处理的分发信息，不等于没有许可或自动侵权。保存证明也不保证免于误判。

## 4. 候选与试听

通常给2–3条有差异的候选，包含曲名、作者、来源链接、许可、适合理由、建议选段、下载限制和公开范围。最多先找少量高质量候选，不把大列表甩给用户。

合法取得音频后，试听首段、主体和收尾；分析BPM、重复节奏及能量。仅有元数据时只能称为待试听候选。若当前Agent不能实际听音频，可生成可播放试听并标注听审未完成，不能仅用频谱声称好听。

用户要求选音乐时提供候选试听；已授权自主制作或自动选曲时可自行选择并说明依据，不强制再次确认。用户反馈后替换选段与后续切点。确定选段后读取 `music-sync.md` 做同拍分析，之后才锁定分镜时间线。

## 5. 下载与回退

从官方允许的链接下载到项目的本地音乐目录；保留原件，派生剪辑单独保存。检查实际文件类型、时长、采样率与完整性，避免把HTML错误页当音频；计算校验值。

若登录/验证码/下载限制阻止自动化：给出已核验曲目页与需要用户完成的具体一步，用户提供下载后继续。用户已批准的素材可继续做不依赖该下载的内容工作。不要静默换成另一首、生成音乐或来源不明镜像。

不要求用户购买或注册未说明的服务；需要凭证时说明用途，不把凭证写进公开配置。只允许试听的文件不冒充可用于成片的下载。

## 6. 产物与公开范围

写入项目 `music-selection.json`（或已有等价真源）和 `MUSIC-CREDITS.md`。可公开清单与本地私人凭证分开保存，签名下载URL、账号信息和付费证明中的个人信息不提交GitHub。

推荐字段：

```text
title, creator, track_page, provider
license_name, license_version, license_url
checked_at, evidence_path, evidence_notes
video_use: allowed / restricted / unknown
source_redistribution: allowed / restricted / unknown
attribution_text, modification_notice
content_id: declared / not_declared / unknown
local_file, sha256, duration, sample_rate
source_in, source_out, selection_reason
listening_status, download_status
```

`not_declared`只表示页面未声明，不能解读为没有Content ID。许可状态需记录适用条件，不只有一个布尔值。

默认不把原始BGM打包进Skill或演示仓库。公开成片与分发原音频分别判断；需要可复现时提供曲目链接和获取说明。确需公开原文件时，必须有适用再分发依据并附独立许可/署名，不能统一标MIT。

交付时提供可直接粘贴到发布文案或作品说明中的署名；如剪辑、变速、淡出，在同处注明实际修改，并保存在 `MUSIC-CREDITS.md`。默认不把曲名、作者、许可证、`Edited` 等信息烧录到视频或封面，包括右下角常驻小字。自动写署名文件不等于已完成发布署名；发布时按具体许可将所需信息放到观众可访问的说明位置。若具体许可明确要求画面内署名，优先换用符合无角标要求的音乐；无法替换时说明冲突，不擅自加角标或省略许可要求。
