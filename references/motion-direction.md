# 动效设计、技能路由与验证

本文件提供独立的设计规范和可选集成，不包含第三方技能源码或固定视频母版。外部技能负责其引擎契约；本Skill负责活动内容、素材真实性、节奏和交付目标。

## 1. 盘点与选路

读取当前技能目录/会话提供的可用技能和现有工程信息。只使用确实存在且已读取的技能；名字和版本可能不同，以当前入口为准，不硬编码本机路径。

| 当前任务 | 读取与调用路线 | 不要做什么 |
| --- | --- | --- |
| 已有 HyperFrames 工程，或选定该引擎 | `hyperframes`入口 → `hyperframes-core`；动效设计读取`hyperframes-animation`，按索引选相关规则；运镜/分屏/遮罩读取`hyperframes-keyframes`；检查导出读取`hyperframes-cli` | 不把“已安装”写成“已调用” |
| 有具体命名转场或效果 | 上述路线加`hyperframes-registry`，按当前接口搜索、检查候选源码，选择适合素材的组件 | 不把组件名称写成效果已完成；不批量装整个库 |
| 新项目选择 huashu-motion 作为制作引擎 | 读取`huashu-motion`，依其导演、节奏、工程和验收指引完成制作 | 不把其运行时API直接粘入另一个引擎 |
| 用户明确要求艺术化、插画或概念解释片段 | 读取`huashu-art-motion`及当前入口指向的相关风格/镜头规范；在独立片段验证后统一画幅、帧率和品牌 | 不为纪实照片默认添加艺术化效果；不照搬其特定题材要求到所有活动 |
| 只有通用动画/剪辑工具 | 用下面的独立动作规范实现，记录工具、版本和实现限制 | 不假装调用了缺失技能，或声称与增强路线同等效果 |

选择一个主要工程引擎。确有必要时可拼入独立渲染片段，但需检查转场、色彩、字体、帧率、音频偏移。不能同时让多个顶层Skill各自重建brief或接管整个项目。执行外部技能前确认范围适配；如与用户已确认要求冲突，以用户要求为准并说明必要差异。

## 2. 动效计划

先写 `motion-plan.md`，可并入现有分镜，避免重复真源：

- 能力：发现的技能、实际读取的入口、选择的引擎、缺失项。
- 方向：纪实快剪、编辑式拼贴、克制叙事或其他与活动相符的语言。
- 能量：哪里吸引注意、哪里讲内容、哪里停下来读字、哪里收束。
- 每个关键动作：主体、起始状态、中间变化、落位状态、音乐锚点、可读停留、裁切安全区。
- 来源：自行实现或引用组件的名称、版本/来源、许可；第三方代码未经许可不随开源包分发。
- 验证：计划的抽帧位置、连续播放片段、已完成与未完成的检查。

用户要求“炫酷”时，优先通过尺度变化、空间组织、主体连续运动和准确的节拍落位表现；不是增加全屏闪光或每镜同一种弹跳。选择少数互相协调的动作，不堆满整张表。

## 3. 可独立实现的动作规范

以下是按内容选择的动作语义，不是必须按序播放的模板。每项均需按本项目素材重新布局和定时。

| 动作 | 适用内容 | 可见变化与实现要点 | 通过标准 |
| --- | --- | --- | --- |
| 人物节拍快切 | 表情、互动、现场气氛 | 在确认的音乐点切换近景与中景；每张图设置焦点 | 变化来自不同画面，人物脸完整，切点与声音对应 |
| 分屏集结 | 多人参与、不同动作并行 | 从单画面到2–3个独立裁切窗，按音乐顺序入场，最终稳定 | 各窗都有清晰主体，不因统一居中截掉脸；接缝不压字 |
| 照片空间展开 | 展现参与范围、由个人到全场 | 锚定一个主体，镜头拉远或邻近照片展开，形成有层次的集合 | 观众能跟随同一锚点；不是整页淡出再换另一页 |
| 聚焦穿入 | 从全场进入一个内容点 | 集合中选定一张照片，保留主体连续性扩大到主画面 | 中间过程不跳位置、不意外变图；落位能接下一镜 |
| 标题节拍落位 | 核心主题、编号系列 | 字块与画面同步出现，或预先启动后在鼓点落稳；短促收势 | 看的是同一音乐相位，文本落位而非动画起点被对齐 |
| 边界揭示 | 话题切换或照片换组 | 使用移动边界揭开下一个画面；文字与照片分层 | 无持续残字、遮挡或未清理的色块，方向与前后镜头一致 |
| 步骤汇聚 | 从资料到成果、可复用方法 | 几个有含义的对象汇入一个容器，再输出结果 | 观众读完标签后才汇聚；文本重叠前隐藏或错位安排 |
| 收束定格 | 合照、邀请、品牌结尾 | 动作收住，合照完整，邀请稳定出现 | 留出阅读时间，末帧可独立成为清楚的结束画面 |

实现时将被剪辑的时段与内部运动分开。使用可寻址的时间线，明确起止状态，保证任意时间跳转与顺序播放一致。蒙版、位移、缩放叠加时分别承担明确职责，避免多个动画争写同一属性。

## 4. 先验证关键片段

先做一个约4–8秒或足够证明动作的片段，使用本次素材和正式音乐选段。选最重要、最难的动作，不只测试简单淡入。

检查起始、过渡中段、重拍落位和收势，并正常速度播放。无需用户再次审批已授权的普通修改，但应在发现方向不合适时先修正关键片段，再复制到全片。没有播放能力时标记限制，不把静帧检查看成动作验收。

## 5. 动效验收

用可观察结果回答，不给空泛的“高级/炫酷”评分：

- 主体真的移动、集合、展开或变换布局了吗？还是只有静图加透明度？
- 连续镜头是否一直同向推近？如果是，有没有内容上的理由？
- 高能段之后是否有可读的稳定段？静止是否服务于阅读或情绪？
- 动作中段有没有脸被裁、字重叠、分隔线压字、图层闪现？
- 音乐卡点是否检查最终编码文件，而不只是时间线数字？
- 实际实现和计划动作一致吗？缺失项是否明确写进交付说明？

每个承诺的关键动作记录：`planned / implemented / visually_checked / playback_checked`。未观看的项目不能标通过。要求动效丰富却只有慢缩放和淡入时，应重新设计，而不是仅修改报告措辞。

## 参考边界

此路由在编写时检查过 HyperFrames 的 animation/keyframes/registry 入口，以及 huashu-motion、huashu-art-motion 的本地入口。只记录集成方式与独立规范；不随包复制外部指令、字体、引擎或动画代码。版本升级后依据实际入口重新确认能力。尚未通过本Skill的新公开样例验证，不承诺复现任何旧视频的效果。
